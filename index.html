About

A quality engineer's
approach to AI.

I've spent 15+ years in Quality Engineering: testing distributed systems, designing automation frameworks, and leading QE teams as SDET, Tech Lead, Test Manager and now Staff Engineer specializing in quality.

That work trains one instinct above all: how complex systems fail. Boundary conditions, reproducibility and failure modes are exactly what AI systems lack today. LLMs are non-deterministic, agents loop, and tools break.

So I build from first principles: neural networks in PyTorch, and now an AI agent engine in Rust where the loop is deterministic, every run is traced, and every test replays the same way. I don't use wrappers. I want to understand every line.

kritaka-agent · Rust + Python · active

kritaka-agent 🦀🤖

A small AI agent engine, not a harness. A Rust core owns the state machine and the rules, Python handles IO through PyO3, and a 3B model runs locally on my laptop through Ollama. It uses no agent framework. I wanted to know what actually happens inside one.

  • Agent states as Rust enums. An invalid state doesn't compile.
  • Think → act → observe loop on local Llama 3.2 3B with tool calling.
  • Safe tools: an AST-based calculator with no eval(), and a UTC clock.
  • JSONL trace of every run, step by step, so I can see why it acted.
  • Deterministic tests: a scripted model replays recorded conversations.
  • CI from day one: rustfmt, clippy -D warnings, cargo test and pytest. Design decisions are recorded as ADRs.
